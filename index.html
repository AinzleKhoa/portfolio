AnSite: Camera-Based Safety Platform for Factories

Lead Developer | Capstone Project & Startup | NestJS, TypeScript, PostgreSQL, TypeORM, Socket.IO, React, Python, MediaMTX, Docker, Caddy, GitHub Actions

May 2026 - Present

Inspired by my OJT work on VMS at Rikkeisoft.

  • Split the system by workload: a Python edge agent on the factory LAN handles camera streams and YOLO/VLM detection, while a NestJS cloud API owns the database, so heavy AI load cannot take down the dashboard.
  • Diagnosed a concurrency bug where a lock held during slow work (image processing, uploads) blocked config updates for 71 s; narrowing the lock cut the delay to under 0.4 s, with a regression test.
  • Built the NestJS alert ingestion API with idempotent writes (retries with the same event ID never duplicate an alert), composite PostgreSQL indexes for per-organization queries, and real-time push via Socket.IO rooms.
  • Delivered alerts beyond the dashboard: each alert keeps its evidence image and is pushed to a Zalo bot with the photo, re-sending identical bytes on retry.
  • Secured live camera viewing: the API issues short-lived HMAC-signed session tokens, and the MediaMTX gateway checks every stream request against an internal auth endpoint (kept off the public internet behind Caddy) before a viewer gets video.
  • Gave every edge device its own credential, stored as a SHA-256 hash and verified in constant time, and wrapped activation and revocation in database transactions so each one either completes fully or changes nothing.
  • Hardened the API with role-based guards on organization-scoped data, input validation (class-validator), Helmet security headers and rate limits, with stricter limits on login and device activation.
  • Deployed to a Linux VPS with GitHub Actions CI and 2,800+ automated tests across API, web and edge; changes follow a written plan with acceptance checks before AI agents implement them, then a separate review.
